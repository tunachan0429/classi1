# 過去問 自動答え合わせツール

自分で作った公開サイトの4択過去問（ア/イ/ウ/エ）を、ブラウザ自動操作で読み込み、
Gemini（無料枠）に解かせて、正解の選択肢を自動でクリックする学習補助ツールです。

> 自分の学習（過去問の答え合わせ）用の補助ツールです。他者が運営する試験の不正回答には使わないでください。

## しくみ

```
run.bat 起動
  → Python + Playwright がブラウザを起動
  → 指定URLの問題ページを開く
  → 問題エリア(表・図を含む)をスクショ + テキスト抽出
  → Gemini(gemini-2.5-flash)に送って ア/イ/ウ/エ を判定
  → 対応するラジオボタンにカーソルを動かしてクリック
  → 結果をコンソールに一覧表示
```

## 必要なもの

- Windows PC
- Python 3.10 以上（[python.org](https://www.python.org/downloads/) からインストール。インストール時に **"Add Python to PATH"** に必ずチェック）
- Gemini の API キー（無料）: [Google AI Studio](https://aistudio.google.com/apikey) で取得

## セットアップ（初回だけ）

1. このフォルダ内の `.env.example` をコピーして、ファイル名を `.env` に変更する
2. `.env` をメモ帳などで開き、次の2つを設定する
   - `GEMINI_API_KEY` … 取得したAPIキー
   - `QUIZ_URL` … 問題ページのURL
   - （ログインが必要なサイトなら、後述の「ログインが必要なサイトの場合」も設定する）
3. `run.bat` をダブルクリック
   - 初回だけ、自動で環境構築（仮想環境作成・ライブラリ・ブラウザのインストール）が走ります（数分）

## 使い方

- `run.bat` をダブルクリックするだけ
- ブラウザが立ち上がり、赤い点（カーソル）が動いてラジオボタンを選択します
- 終わると結果一覧が表示され、Enter で閉じます

### コマンドの追加オプション

```
run.bat --url https://example.com/quiz2   （URLをその場で指定）
run.bat --headless                          （ブラウザを表示せず裏で実行）
run.bat --no-submit                         （採点ボタンを押さない）
```

## ログインが必要なサイトの場合（自分のサイト用）

問題ページを開く前にログインが必要な場合は、`.env` に次を設定してください。
**`LOGIN_URL` / `LOGIN_USER` / `LOGIN_PASS` の3つがすべて埋まっているとログインを実行**します（1つでも空ならログインはスキップ）。

```
LOGIN_URL=https://あなたのサイト/login
LOGIN_USER=あなたのユーザー名
LOGIN_PASS=あなたのパスワード
```

ログイン後、同じブラウザのまま `QUIZ_URL` の問題ページへ進むので、セッション（ログイン状態）はそのまま引き継がれます。

入力欄やボタンの位置が既定と違う場合は、次のセレクタを実際のHTMLに合わせて変更してください。

| 項目 | 説明 | 既定値 |
|------|------|--------|
| `LOGIN_USER_SELECTOR` | ユーザー名の入力欄 | `input[name=username]` |
| `LOGIN_PASS_SELECTOR` | パスワードの入力欄 | `input[type=password]` |
| `LOGIN_BUTTON_SELECTOR` | ログインボタン | `button[type=submit]` |
| `LOGIN_NEXT_SELECTOR` | 【2段階ログイン用】ユーザー名の後に押す「次へ」ボタン（任意） | （空） |
| `LOGIN_SUCCESS_SELECTOR` | ログイン後だけ現れる要素（成功確認用。任意） | （空＝確認しない） |

> `LOGIN_SUCCESS_SELECTOR` を設定しておくと、ログインに失敗したとき（パスワード違いなど）にその場で気づけるのでおすすめです。

### 2段階ログイン（ユーザー名 → 次へ → パスワード）のサイト

「ユーザー名を入れて『次へ』を押すと、あとからパスワード欄が出てくる」タイプのサイト
（Angular製のログイン画面などによくあります）にも対応しています。

- 基本は **設定なしでも自動対応**します（ユーザー名入力後、パスワード欄が見えなければ自動で「次へ」に相当するボタンを押し、パスワード欄が表示されるまで待ってから入力します）。
- うまく進まない場合は、`LOGIN_NEXT_SELECTOR` に「次へ」ボタンのセレクタを指定してください。

```
LOGIN_NEXT_SELECTOR=button[type=submit]   （例。実際の「次へ」ボタンに合わせて）
```

> 以前出ていた `Page.fill: Timeout ... input[type=password] ... element is not visible` は、
> この2段階ログイン（パスワード欄が最初は非表示）が原因でした。上記の対応で解消します。

### ログインボタンが `button[type=submit]` でないサイト

`login button not found`（ログインボタンが見つからない）と出た場合でも、
**ボタンが見つからなければ入力欄で自動的に Enter を押して送信**します。
そのため多くのサイトは `LOGIN_BUTTON_SELECTOR` を変えなくてもログインできます。

- もし Enter では送信できないサイトなら、`LOGIN_BUTTON_SELECTOR` に実際のログインボタンの
  セレクタ（例 `button.login`, `input[type=submit]` など）を設定してください。
- ログインが成功したか確実に判定するため、`LOGIN_SUCCESS_SELECTOR` の設定を推奨します。

### ログインしても問題ページでまたログイン画面が出るサイト

「先にログインしても、問題URLに移動するとログイン状態が消えて、またログイン画面が出る」
というサイトがあります（ログイン状態をページ内メモリだけで持つSPAや、保護ページに直接
アクセスするとログインへ飛ばすサイトなど）。

これに対応するため、**問題ページを開いたときにログイン画面が出ていたら、その場で自動的に
もう一度ログインします**。ログイン後に元の問題ページへ自動で戻らないサイトの場合は、
問題URLをもう一度開き直します。特別な設定は不要です。

> それでも問題ページに入れない場合は、`LOGIN_USER_SELECTOR` / `LOGIN_PASS_SELECTOR` /
> `LOGIN_BUTTON_SELECTOR` が、そのログイン画面の実際のHTMLに合っているか確認してください。

> ⚠️ `.env` にはパスワードが平文で入ります。`.env` は `.gitignore` 済みで共有されませんが、PCの取り扱いには注意してください。**このログイン機能は自分自身のサイト／アカウント用です。**

## 調整用の設定（.env）

| 項目 | 説明 |
|------|------|
| `GEMINI_MODEL` | 使用モデル（既定 `gemini-2.5-flash`） |
| `HEADLESS` | `true` でブラウザ非表示 |
| `SLOW_MO_MS` | 動作の遅延（見やすさ調整） |
| `QUESTION_SELECTOR` | 問題全体を囲む要素（既定 `tui-section-question`） |
| `FORM_SELECTOR` | 解答欄（既定 `tui-single-select-form`） |
| `RADIO_NAME` | ラジオの name（既定 `answer-option`） |
| `SUBMIT_SELECTOR` | 採点/送信ボタン（使うときだけ設定） |

## 1問ずつ「回答ボタンで次へ」進むサイト

「1問表示 → 選択 → 『回答』ボタンを押す → 次の問題」…という形式のサイトに対応しています。
問題がある限り、**選択 → 回答ボタン → 次の問題** を自動でどんどん繰り返します。

- 「回答」ボタンは、**設定なしでも文言（回答／解答／次へ など）から自動で探します**。
- うまく見つからない・別のボタンを押してしまう場合は、`.env` の `ANSWER_BUTTON_SELECTOR` に
  実際の回答ボタンのセレクタを設定してください。
- 回答後に「正解/不正解」などのフィードバック画面が出て、さらに「次へ」を押す必要がある場合も
  自動で「次へ」を押します（`NEXT_SELECTOR` で明示指定も可能）。
- 次の問題が出なくなったら「全問終了」とみなして自動で止まります。
- 暴走防止に `MAX_QUESTIONS`（既定200問）で上限を設けています。`--max` でもその場指定できます。

| 項目 | 説明 | 既定値 |
|------|------|--------|
| `ANSWER_BUTTON_SELECTOR` | 1問ごとの「回答」ボタン（空＝文言から自動検出） | （空） |
| `NEXT_SELECTOR` | フィードバック後の「次へ」ボタン（空＝文言から自動検出） | （空） |
| `MAX_QUESTIONS` | 解く問題数の上限 | `200` |
| `QUESTION_TIMEOUT_MS` | 次の問題を待つ時間（超えたら終了） | `20000` |
| `SUBMIT_SELECTOR` | 全問終了後に一度だけ押す採点/送信ボタン（任意） | （空） |

> 回答ボタンが見つからずすぐ終わってしまう場合は、実行時のコンソールに出る
> `回答ボタンが見つかりませんでした` の直後の案内に従って `ANSWER_BUTTON_SELECTOR` を設定してください。

### 「解答を中断しますか?」モーダルが毎回出てしまう場合

「解答を中断しますか？」のようなモーダルが出るのは、多くの場合
**ツールが『次へ』ではなく『解答を中断する』ボタンを間違って押している**のが原因です。
（「解答」という文字を含むボタンを誤検出していました）

これを防ぐため、次のように改善しています。

- **「中断」「中止」「やめる」「戻る」などを含むボタンは絶対に押しません。**
- 選択後に押すボタンは、`回答` 系 → `次へ` 系の順で自動的に探します（中断ボタンは除外）。
- 万一「中断しますか?」モーダルが出てしまった場合は、**自動で「キャンセル」を押して閉じ**、
  中断せずに進行を続けます。

それでも正しいボタンを押せない場合は、`.env` の `ANSWER_BUTTON_SELECTOR` に
**「次へ」ボタンのセレクタ**を直接指定してください（例 `button.next-question` など）。

> ちなみに、ブラウザ標準の確認ダイアログ（`confirm` / ページ離脱の確認）も自動処理します。
> その挙動は `DIALOG_ACTION`（`accept`＝OK / `dismiss`＝キャンセル、既定 `accept`）で変えられます。

> 余計なボタンを押さないよう、「次へ」ボタンの自動クリックは既定でオフです。
> フィードバック画面の「次へ」を押す必要があるサイトでは、`NEXT_SELECTOR` を設定するか
> `AUTO_NEXT=true` にしてください。

## Gemini が混雑している（503）とき

`503 UNAVAILABLE`（アクセス集中）が出ても、**自動で数回リトライ**します。
それでも復旧しない場合は、時間をおいて再実行するか、`.env` の `GEMINI_MODEL` を
別のモデル（例 `gemini-2.0-flash`）に変えて試してください。

## 課題を自動で巡回するモード（全自動）

ログイン後の画面遷移まで含めて全部自動化できます。次の流れを、未完了の課題が無くなるまで繰り返します。

```
ホーム画面
  → 「学習トレーニング」をクリック
  → 「課題」をクリック
  → 課題一覧から「未完了」の課題を上から選択
  → 課題詳細画面(ステップ一覧)へ
      ├ ステップ(テストを解く / おすすめ演習 …)の「開始する」を押す
      ├ 問題を1問ずつ解く(選択→回答→次へ)
      ├ 「答え合わせへ」→「課題詳細画面へ」で詳細画面に戻る
      └ 「開始する」が無くなる(全ステップ完了)まで繰り返す
  → 次の未完了の課題へ
```

> 課題は「テストを解く」だけでなく「おすすめ演習」など**複数のステップ**があり、
> すべてのステップを終えないと「課題完了」になりません。
> このツールは**課題詳細画面に「開始する」ボタンが無くなるまで**、各ステップを自動で解きます。

### 使い方

1. `.env` で `AUTO_ASSIGNMENTS=true` にする
2. `QUIZ_URL` に **ログイン後に最初に表示されるホーム画面のURL** を設定する
3. （必要なら）ログイン情報を設定する
4. `run.bat` を実行（`run.bat --auto-assignments` でもオンにできます）

### 調整用の設定

各画面のボタンは文言で探します。表示が違う場合は `.env` で変更してください。

| 項目 | 説明 | 既定値 |
|------|------|--------|
| `AUTO_ASSIGNMENTS` | 自動巡回モードのオン/オフ | `false` |
| `TRAINING_TEXT` | 学習トレーニングのボタン文言 | `学習トレーニング` |
| `ASSIGNMENT_MENU_TEXT` | 課題メニューの文言 | `課題` |
| `START_TEXT` | 開始ボタンの文言 | `開始する` |
| `GRADING_TEXT` | 答え合わせボタンの文言 | `答え合わせ` |
| `BACK_TO_LIST_TEXT` | 一覧へ戻るボタンの文言 | `課題詳細画面へ` |
| `ASSIGNMENT_SELECTOR` | 課題カードのCSSセレクタ（空＝自動推定） | （空） |
| `INCOMPLETE_TEXT` | 未完了を表す文言 | `未完了` |
| `MAX_ASSIGNMENTS` | 巡回する課題数の上限 | `50` |
| `MAX_STEPS` | 1課題あたりのステップ数の上限 | `20` |

> **課題がうまく選択できない場合**は、`ASSIGNMENT_SELECTOR` に課題一覧の1件分のカードの
> CSSセレクタを指定してください。分からなければ、課題一覧のHTML（カード1件分）を見せてもらえれば設定します。

> 従来どおり「1つの問題ページだけ解く」使い方をしたい場合は `AUTO_ASSIGNMENTS=false`（既定）のまま、
> `QUIZ_URL` に問題ページのURLを設定してください。

## 注意点

- Gemini の解答は **100%正解ではありません**。答え合わせの参考として使ってください。
- サイトのHTML構造が想定と違う場合は、`.env` のセレクタを実際の構造に合わせて変更してください。
```
